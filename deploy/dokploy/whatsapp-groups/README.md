# Rotating group media in the Postiz calendar

Run rotation.py with a private config at /opt/postiz-amssoft/automation/whatsapp-groups/config.json. Install the sibling common/workflow_cancel.py module alongside the automation directories. A rolling window of three native Postiz slots is created at 06:00, 12:00 and 18:00 in the configured timezone. Each slot selects one active asset in persistent discovery order and wraps around the list. New files append; reserved slots retain media only while the asset remains active.

Removing media cancels queued future reservations through the Postiz API, confirms deletion, and verifies native Temporal executions are closed before releasing a reservation. The common helper also reconciles an execution when a previous deletion already marked the post deleted. Ambiguous creation, unconfirmed cancellation, and requests within three minutes of dispatch require review. Started or published deliveries are never blindly rewritten.

One aggregate Postiz channel sends the same asset to the private policy snapshot. No group IDs, names or tokens belong in this repository. An empty folder creates no new posts and retires removed future reservations. Accept stable MP4/JPEG/PNG up to 32 MiB, probe new media in a disposable container without network, credentials or write mounts, and upload on demand. Run as a oneshot timer every minute. Postiz owns dates; WAHA only executes immediate delivery requests. Use atomic rename after copying media.
